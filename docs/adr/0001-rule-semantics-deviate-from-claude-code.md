# 规则语义以 Claude Code 的 `.claude/rules/` 为基线，但在若干点上有意偏离

dsh 今天只有一套指令加载机制：`@deepseek-ai/dsh-agent-instructions` 按固定文件名
（`AGENTS.md` / `CLAUDE.md`）沿祖先目录链加载，**明确不解释 `.claude/rules/`**。要做
`dsh-rules` 插件复刻 Claude Code 的「按路径生效的规则」，就得自己实现发现、匹配与注入。
Claude Code 2.1.307 的语义（官方文档 + 本地包 + CHANGELOG）已固定下来，其中格式、基准目录、
触发集、常驻规则四条按原样对齐；下面七条不照抄，各有具体代价。

## 偏离清单

| 项 | Claude Code | dsh-rules | 为什么 |
|---|---|---|---|
| 规则索引 | **不注入**任何索引，模型不知道未加载的规则存在 | 会话开始注入 `name + paths` 的索引 | 上游把「让模型知道有这些规则」留给了用户：参考项目只能手写索引并用 `test_rules_index.py` 钉住。dsh 在会话开始有一个稳定时机，一条小消息就能消掉这份人工成本 |
| 注入形态 | `Contents of <path>:` 头的 memory 附件 | 沿用 dsh 的 `<system-reminder>` 包裹 + user 角色消息 | 与宿主既有的 AGENTS.md 注入同形；模型已经会读这种形态，不必为规则再教一遍 |
| glob 语义 | `*` **跨目录**（`*.md` 匹配任意深度） | 标准语义：`*` 不跨目录，跨目录写 `**` | 复刻一个只存在于 Claude Code 的方言，维护成本全在自己身上。现有规则集全部用 `**/`，标准语义下行为完全一致 |
| frontmatter 坏了 | **fail open**：当成没有 `paths`，于是全量注入 | **fail closed**：整条不注入，索引里标「解析失败」 | 一条本该只对某目录生效的约定变成每次会话的全局约定，是静默变差；本仓的口径是「兜底朝响亮失败」 |
| 单文件上限 | 1 MB | 64 KB | 与 dsh 自己的 `agent-instructions` 预算（`65536`）一致。同一宿主上两类指令文件的预算不该差 16 倍 |
| bash 触发 | 认 `cat` / `head` / `tail` / `sed -n` / `grep` 对单文件的读取 | 只认保守子集：单条命令、无管道、无通配、恰好一个确定文件路径、且命令属于上述几个 | dsh 的 bash 工具不提供可靠路径，只能解析命令文本。误判面必须收窄，宁可少触发 |
| 作用域 | 有用户级 `~/.claude/rules/`，子目录也放 `.claude/rules/` 按需加载 | 都不做：只做「cwd + 祖先目录」的 `.dsh/rules/` | 先把「单项目内按路径注入」这个核心机制做对。两者都是纯加法，留待后续 |

## 后果

- **从 Claude Code 迁过来的仓库不会直接生效**：目录名不同、`*` 语义不同、用户级规则不生效。
  配置项 `roots` 是唯一的人工兼容路径（默认仍是 `['.dsh/rules']`）。
- 规则以 **user 消息**形态出现，措辞必须明确指向「以下是本仓的约定」，否则会被当成新的用户请求。
- fail closed 让坏 frontmatter 的规则完全沉默；索引里的标记是唯一线索，**它必须同时进日志**
  ——本插件没有 UI，日志是唯一的事后可观测面。
- bash 命令解析是唯一有误判风险的部件，因此与核心闭环分开交付。

## 考虑过但不选的

- **严格复刻 Claude Code**：`*` 跨目录与 1MB 上限都不是我们会主动选的设计，复刻它们等于把上游的
  偶然变成自己的负担；而前四条里真正值钱的（索引、注入形态、fail closed）恰恰是偏离的那几条。
- **完全不参考 Claude Code、自造语义**：`paths` frontmatter + 「相对规则所属目录的父目录」这套心智
  用户已经在用，重造一套方言收益为零。
