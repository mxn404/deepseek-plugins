# 开关位置是会话状态，不是项目偏好

`/new`（= `/clear`，由 `dsh-new-session` 提供）在**原地**开新对话：新会话沿用当前会话的
工作目录，所以它天然会落进当前副本。这条路径第一次造出「会话在副本里，但项目的隔离默认
是关」的组合，而开关位置当时被当成「这个会话该不该在副本里」的证据。于是新会话被搬进
副本后，开关的首次检查读到「在副本里 + 默认关」，判定这种会话不应该在副本里，执行
`release` 把新会话搬回源检出。另一个可达路径更隐蔽：复用页面里已经检查过的空白会话时，
空白判断按不可变的创建目录做，接管之后开关不再复查，按钮停在陈旧的「已关」，而会话
其实在副本里。

两个现象的共同根因是同一个代理判据：把**位置**（这条会话此刻在哪跑）当成**意图**（这个
项目的新会话要不要隔离）。后者从来只是项目级默认，不是对已有会话的裁决。`/new` 之前没有
任何路径能合法产生「当前副本 + 项目默认关」，所以这个代理一直没被戳破。

## 决定

- **开关位置 = 会话状态。** `ready`（会话在副本里）⇒ 开；其余阶段 ⇒ **隔离默认**。
  `aria-checked`、点击语义与文案都读同一个派生位置，控件与事实不再打架。
- **项目级的值改称隔离默认。** 它只决定一个还没建副本的新会话要不要隔离；拨动开关仍然把
  它按项目写入。它不再回答「已经在副本里的会话该不该留下」。
- **挂载不搬会话。** 删除「在副本里 + 默认关 ⇒ 自动 `release`」。已经在副本里的会话只由
  用户拨回离开；`/new` 继承来的副本不会被项目默认移走。
- **投影驱动的重查。** 开关订阅工作目录投影，目录一变就做一次完整检查（可能 `prepare`），
  并与创建/离开互斥。重查允许补建，但只在会话仍然空白、且隔离默认仍为开时；离开失败后的
  兜底重读只更新位置，不创建也不离开。
- **离开别人的副本是普通离开。** 归属不是本会话的副本（`/new` 继承来的、其他会话留下的）
  在离开时返回 `keptReason: 'not-owned'`：会话回到源检出，副本留在磁盘上，**不**弹一次性
  提示、**不**计入侧边栏清理计数，只在开关的 hover 里说明。它不是遗留，仍会出现在面板里，
  由拥有它的会话或面板的显式丢弃处理。
- **撤销边界沿用 ADR-0006。** 「离开 = 撤销，不是回收」继续成立：只有显式离开会撤销副本，
  且只有开关为这条会话创建、仍停在基点、没有未提交改动的副本才被删。`not-owned` 不是新
  语义，只是这条边界在「副本存在但归属不是自己」时的正常结果——`/new` 让它从异常路径变
  成常规路径。
- **不转移归属、不建第二份副本。** `/new` 不 `prepare`，继承的副本仍记在创建它的会话名下
  （Git admin dir 里的 `sessionId` 不变）；新会话离开时只动目录，不动副本。
- **wire 字段不变，口径收紧。** `status` / `list` / `scope` 的字段照旧；变的是 `release`
  对 `not-owned` 的登记行为，以及 `ListValue.keptCopies` 只数有内容与删除失败的保留。

## 考虑过但不选的

- **挂载时按项目默认自动 `release`（旧行为）**：这正是 bug。它把「新会话要不要隔离」当成
  「在副本里该不该留」，会用一次静默的目录搬迁推翻用户已经在副本里进行的工作。
- **为 `/new` 再建一份副本**：每次 `/new` 都从源检出的基点重新开始，用户未提交的改动、
  当前分支与工作现场全部丢失；副本池还会随 `/clear` 次数增长。
- **把继承副本的归属转给新会话**：新会话离开时会删掉旧会话仍可能在工作用的副本，等于把
  「离开」变成一次跨会话的回收，违反 ADR-0006。
- **不派生位置，继续显示项目默认**：这是第二条现象的直接来源——控件与事实互相矛盾。
- **对 `not-owned` 的保留弹一次性提示并计入清理计数**：会用「垃圾」的语气报告一次正常的
  离开。ADR-0006 的提示本来用于无法证明归属的意外；`/new` 继承之后它是常规路径，只该在
  hover 里解释自己。
- **中断的离开自动补完**：页面刷新打断一次离开时，保留「位置与重查后的事实一致」即可；
  自动补完会在用户没再要求的情况下搬动会话。
- **在面板里显示每份历史副本的基点**：`git worktree list` 不记录基点，插件也没有持久化过；
  要做就得新增一层存储，还要处理「这条历史没记过」。基点是创建那一刻的事实，不是可回溯
  的会话属性（ADR-0005 已否过一次）。

## 后果

- **开关与事实一致**：`/new` 出的新会话在副本里时，开关显示开与副本名；项目默认只影响之
  后新建的会话。
- **一个控件仍表达两件事，但边界被写清楚了**：在空白会话的 hero 上，位置读作「我在副本里
  吗」，不在副本时读作「这个项目的新会话要不要隔离」。ADR-0006 拒绝把开关常驻到非空白
  会话，用的正是「两件事混在一个控件里会误读」的理由；本 ADR 保持 hero-only，非空白会话
  的「我在副本里」交给头部 badge 表达。
- **继承的副本在离开后仍在池里**：新会话回到源检出，但副本属于旧会话，可能还在被使用。
  面板继续列出它，清理只能显式做。
- **清理计数更诚实**：`not-owned` 的保留不再登记为「宿主保留的副本」，`keptCopies` 只覆盖
  有内容（`dirty`）与删除失败的保留。
- **通知面收窄**：一次性提示只对「有内容而保留」与「离开失败」出现；`not-owned` 只在
  hover 里解释。
- **重查有成本**：每次工作目录投影变化多一次 `status` 往返（必要时一次 `prepare`），换来
  界面不再停在陈旧位置。创建与离开进行时互斥，竞态由状态机承担，不靠时序。
- **按 patch 发布（0.5.1）**：这是版本规则生效后的第一次 patch 发布，版本位规则见
  [ADR-0008](0008-version-bumps-only-patch.md) 与 [`.dsh/rules/versioning.md`](../../.dsh/rules/versioning.md)。
