# 离开即撤销：归属持久化、失败可见、遗留分支可清理

拨回 Worktree 开关（离开）之后，本地分支还在。查下来不是「忘了删」：正常路径确实先删
checkout、再 `git branch -D`，七十条宿主测试也全绿。遗留来自三处——「这份副本归开关管」
只存在宿主内存里（重启即失忆）、删除失败的异常被 release 的 catch 吞成「保留」、以及
worktree 注册被 prune 之后，面板只读 `git worktree list`，于是「目录没了、只剩分支」的
孤儿再也列不出来。本 ADR 固定三件事：离开的语义边界、归属存在哪里、以及删不掉之后由谁
收尾。会话关闭/删除不在本 ADR 范围内：宿主没有可挂接的会话关闭 seam（见「考虑过但不选
的」），插件区分不了「关闭」与「归档」。

## 决定

- **离开 = 撤销，不是回收。** 只有「开关为这个会话创建、且没有产生提交、没有未提交改动」
  的副本，才在离开时被删掉。有内容的、归属不明的，一律保留。「不提供自动回收」这条
  ADR-0005 的取舍继续成立，本 ADR 只是把「撤销」与「回收」的界线写清楚。
- **归属持久化在副本自己的 Git admin dir。** 创建成功后往
  `.git/worktrees/<名字>/dsh-worktree-switch.json` 写 `{ sessionId, createdAt, baseCommit }`。
  它随 worktree 删除自动消失，不脏工作区（工作区里不会多出未跟踪文件），宿主重启后仍然
  读得到。读不到或解析失败一律视为无归属，不猜。
- **旧副本不补写标记。** 升级前就存在的副本、以及升级时某个会话正运行在其中的副本，都算
  归属不明；离开时保留并如实提示。补写标记会把手工 `git worktree add` 出来的副本误认成
  开关建的，而那份副本可能带着提交。
- **删除失败必须可见。** `ReleaseValue` 增加 `keptReason`（`dirty` / `not-owned` /
  `failed`）与 `error?`；只有 dirty 与 not-owned 允许返回 kept，删除失败必须抛错，不再
  被吞成「保留」。失败与保留通过帧级浮层（`shell.overlay`）的一次性提示告知，并给出
  「打开面板」动作；侧边栏入口在有待清理项时显示计数。不提供「重试清理」按钮——离开的
  语义已经完成，重复执行它只会让用户在脏副本上反复点一个永远不会成功的按钮。
- **遗留分支是一等公民。** 名字符合生成格式（`^[a-z]+-[a-z]+-[0-9a-f]{4}$`）、但不是任何
  checkout 的 HEAD、也不是主检出 HEAD 的分支，在面板里单独成组，行内显示提交数、最近
  提交 subject 与时间，删除必须二次确认。不显示「是否已合并」：squash merge 之后 Git 认为
  没合并，这一列会给出让人误删的错误信号。
- **prunable 的行仍是副本。** 目录被手工删掉、Git 注册还在的副本，留在副本列表里并标明
  「目录已丢失」，清理走同一套丢弃动词（先删分支、再 prune）。把它并进「遗留分支」会让
  那个术语同时指两种东西。
- **detached 的副本只展示、永不删分支。** 现有代码在 `branch` 缺失时回退成目录名，可能
  删掉同名但无关的分支；这条回退要删掉，detached 副本的丢弃只做 checkout 移除。
- **当前副本在会话头部可见。** 头部工具位（`conversation.session.header.utilities`）常驻
  `⎇ 分支名`；完整绝对路径、仓库根、未提交数放 tooltip；点击打开面板并高亮当前副本。
  头部只在非 blank 会话渲染，与只在 hero 出现的开关天然互补。数据走新增的轻量 `scope`
  动词（先读宿主侧按会话记录的副本，读不到再对当前目录做一次 `worktreeAt` 检测），
  **不做**源仓库 status——那是 `status` 为 hero 开关准备的重活。客户端在
  `useProjection('workingDirectory')` 变化时重查。
- **清理发生在面板，不发生在离开。** 离开只负责「回到源检出 + 撤销该撤销的」；被保留的
  副本与遗留分支都由面板的显式动作处理，二次确认不能省。

## 考虑过但不选的

- **把归属写进池里的一个总状态文件**（`.dsh/worktrees/.dsh-worktree-switch.json`）：跨副本
  存活、实现更简单，但池可以被用户整体删除或挪走，它就成了第二份事实来源。
- **把归属写进会话记录（新 session 事件或投影）**：最持久，目录被 `rm`、worktree 被 prune
  之后仍知道哪个会话拥有过哪份副本；但改会话格式、跨版本成本最高。留作以后真需要
  「目录都没了还能追溯归属」时的升级路径。当前的遗留分支清理不依赖归属，所以不急。
- **无状态猜测**（干净就删、分支 tip 是某个祖先就删）：无法区分「开关建的干净副本」与
  「用户手工建的干净副本」；删错一次就是真的丢工作。
- **升级时给当前会话所在的副本补写标记**：无法证明它是开关建的，等于把猜写进持久化。
- **自动回收 / 关闭会话即回收**：dsh 0.2.2-rc.1 没有 session/closed、session/deleted、
  agent/stopped 之类的 seam；侧边栏的「删除」实际是归档，只写归档集合，不碰磁盘；唯一的
  宿主拆解事件是 `agent/disposed` / `session/disposed`，语义是「离开 store」，不是「用户
  关掉了这个会话」。在这个 seam 上删副本，会在宿主重启或崩溃恢复时误伤。
- **给失败提示加「重试清理」**：见上，离开已经完成，重试只会制造一个必然失败的动作。
- **`merged` 标记或 `git branch --merged` 判断**：squash merge 后 Git 认为分支没合并。
- **badge 数据直接复用 `status`**：每次挂载都要跑源仓库 `git status --porcelain`，对常驻
  头部来说太重；`status` 保持原样，给 hero 开关用。
- **badge 数据纯客户端推断**（`workingDirectory` 投影 + 池路径模式）：拿不到分支、也拿不到
  服务实际配置的池位置；宿主重启后投影还要等会话 resume 才有值，会有一段时间显示不出。
- **放宽现有开关、让它在非 hero 会话常驻**：输入框工具行会被占用，且开关的语义（「这个
  项目的新会话要不要隔离」）与「我在副本里的只读状态」是两件事，混在一个控件里会反复被
  误读。
- **把遗留分支并进 prunable 的清理路径**：两者一个还有 admin dir、一个没有；合并会让
  「丢弃」对两种对象给出不同的二次确认语义。

## 后果

- **wire 契约变更**：`ReleaseValue`、`ListValue` 增字段，新增 `scope` 动词。宿主半与浏览器
  半在同一个包里、同版本加载，所以不存在跨版本组合；但页面与宿主需要一起重启，发版按
  minor（0.5.0）走 changeset。
- **旧副本要手动清一次**：升级前留下的副本没有标记，离开时会被保留并提示「归属不明」。
  这是有意的：宁可提示，不猜。
- **侧边栏计数在宿主重启后退化**：只剩「遗留分支」可数，「被保留的副本」是本次宿主生命
  周期内的知识。README 与面板文案要把这点写明，避免用户以为计数会一直准。
- **badge 在两处不显示**：blank hero（开关还在）与面板页（会话列被替换）。这是槽位本身
  的约束，不是遗漏。
- **归属标记在 `.git/worktrees/` 里**：不进版本库、不进工作区、不产生未跟踪文件，但用户
  `rm -rf` 掉副本目录后，标记要等 Git 注册被 prune 才消失；那期间面板会把该行标成
  「目录已丢失」，走同一套清理。
- **detached 副本永远不会被开关自动删掉**：只展示、只允许显式丢弃 checkout。这比「猜一个
  分支名去删」安全，代价是用户要自己回收它。
- **README 与面板文案要同步**：面板从「只列副本」变成「副本 + 遗留分支」，开关的 hover
  提示要带上 kept 原因，README 的「已知边界」需要新增「不回收、不追溯旧副本」。
